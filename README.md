# КФЗ · сверка с доказательствами

Локальное приложение на русском языке: загрузите КФЗ и первичные документы, нажмите **«Проверить»** и откройте источники каждой суммы. Первая версия предназначена для выданной формы КФЗ: договор `24/03/15-01`, строка **«3 этап, 2026 г.»**, подтверждающий период **01.01.2026–31.05.2026**.

## Быстрый запуск в Docker

Требования: Docker Engine или запущенный Docker Desktop с Linux containers; рекомендуются 4 ГБ свободной памяти. При первой сборке нужен интернет для Python, Debian и пакетов OCR. После сборки распознавание и расчёт работают локально без сети, облачных API и ИИ-моделей.

Из каталога проекта:

```sh
docker build --no-cache -t kfz-local .
docker run -d --name kfz-local -p 127.0.0.1:8501:8501 kfz-local
```

Откройте <http://localhost:8501>. Остановка и удаление контейнера:

```sh
docker stop kfz-local
docker rm kfz-local
```

В образ копируется только код и настройки по разрешённому списку `.dockerignore`. Первичка, ответы, результаты, тестовые копии и каталог `work/` в образ не входят. Загрузки передаются только локальному контейнеру. Остановка с последующим удалением контейнера удаляет его временные файлы.

## Как проверить комплект

1. Распакуйте выданный архив на своём компьютере. В отдельное поле **КФЗ** загрузите PDF карточки.
2. В поле комплекта загрузите подтверждающие PDF, PNG, XLSX, DOCX либо ZIP с комплектом. Эталон `!Правильные_ответы_и_разбор.xlsx` предназначен только для независимой приёмки и не должен быть входом расчёта.
3. Проверьте договор, период и выбранную строку отчёта; нажмите **«Проверить»**.
4. Выберите **0800**. Формула раскрывает каждое слагаемое, исходный текст и фрагмент документа; отдельно открывается графа КФЗ.
5. В журнале проверьте исключённые файлы и причины. Нулевое расхождение означает совпадение в пределах принятых документов, а не доказанную полноту первички.

Для спорного документа откройте вкладку журнала, просмотрите фрагмент, выберите статью или исключение и укажите причину. После сохранения приложение пересчитает результат; решение и прежнее состояние сохраняются в журнале текущей сверки. Дубликат нельзя включить второй раз; для конфликтующих сумм требуется выбрать один документ и исключить другой. Решения живут в текущей сессии, после её завершения их нужно принять заново.

## Контрольные примеры

Это приёмочные ожидания для выданных файлов, а не константы алгоритма:

| Вход | Ожидаемый результат |
|---|---|
| Исходный комплект, январь–май 2026 | 0200: 5 558 474,83; 0300: 1 671 359,96; 0800: 1 133 298,10; 0900: 3 204 744,51 руб. |
| Исходный комплект, статья 0800 | КФЗ 1 145 798,10 − документы 1 133 298,10 = **+12 500,00 руб.** |
| Копия КЛ-31: сумма 270 000,00 → 271 000,00 | Расхождение 0800 уменьшается до **+11 500,00 руб.** |
| Комплект без февральской зарплатной ведомости | 0200 и общий итог: **«Недостаточно данных»**; подтверждённая часть 0200 **4 441 474,83 руб.** |

Итог по четырём верхнеуровневым статьям: в КФЗ **11 580 377,40**, по документам **11 567 877,40**, разница **+12 500,00 руб.**

## Архитектура и правила

Поток: **загрузка → безопасное чтение файлов → текст / OCR / ячейки / строки таблиц → реквизиты и источники → отбор и дубли → суммы Decimal → сравнение с выбранной строкой КФЗ → таблица и доказательства**.

- `app.py`, `ui/` — Streamlit, загрузка, навигация, журнал и просмотр доказательств.
- `kfz_core/` — общее ядро для браузера и автоматической приёмки.
- `config/` — редактируемые признаки статей.
- `tests/` — независимая приёмка; эталон передаётся отдельно, в приложение не импортируется.
- PDF с текстовым слоем читается PyMuPDF с координатами; сканы PDF и PNG — локальным Tesseract `rus+eng`. Плотная строка КФЗ распознаётся по областям граф, с привязкой к странице.
- XLSX читается openpyxl, DOCX — python-docx. Источник хранит исходный текст, значение и адрес ячейки, строки или области страницы.
- При наличии периода услуги используется период. Если есть только дата документа, она служит датой отнесения к проверяемому периоду. Неясная связь требует проверки.
- Деньги представлены `Decimal`, с точностью до копейки. Единая формула разницы: **КФЗ минус документы**. Нижестоящие разбивки повторно не суммируются в общий итог.
- Зарплата: пять месяцев, `Ведомость!C6:C7`. Формула C8 без кэшированного результата пересчитывается из деталей. C6 подтверждает основную зарплату, C7 — доплаты и резерв вместе.
- Взносы: пять месяцев, `Расчет взносов!B6`. A6 — база начисления, не сумма взносов.
- Точные копии сравниваются по SHA-256. Повторные сканы — по реквизитам; разные суммы при совпадающих реквизитах требуют проверки.
- Документ другого договора или периода исключается с отдельной причиной. Ошибка одного файла не останавливает остальные; возможное влияние на статью означает недостаток данных.

## Зависимости и настройки

Python 3.11, Streamlit, openpyxl, python-docx, PyMuPDF, Pillow, pytesseract; Tesseract OCR с русскими и английскими языковыми данными. Основные версии закреплены в `requirements.txt`. При сборке Docker пакеты параллельно устанавливает uv 0.9.9; затем он удаляется из образа. Телеметрия Streamlit отключена, внешние сервисы во время работы не используются.

Для запуска без Docker установите Tesseract `rus+eng`, добавьте его в PATH. В PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
.\.venv\Scripts\python -m streamlit run app.py
```

В Linux/macOS:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m streamlit run app.py
```

Адрес приложения тот же: <http://localhost:8501>. В командах CLI ниже используйте Python созданного окружения либо предварительно активируйте его.

Если Tesseract не в PATH, переменная `TESSERACT_CMD` задаёт полный путь к исполняемому файлу; `TESSDATA_PREFIX` — каталог языковых данных. В Docker эти настройки не требуются.

## Проверка из командной строки и без сети

То же ядро можно вызвать без интерфейса (пути укажите к своим файлам):

```sh
python -m kfz_core --report "/path/to/01_Карточка_учета_фактических_затрат_этап_3.pdf" --documents "/path/to/данные" --output work/result.json --work-dir work/run
```

Независимая приёмка читает эталон отдельным процессом и сначала проверяет исходный комплект:

```sh
python tests/acceptance.py --input "/path/to/данные" --reference "/path/to/reference/!Правильные_ответы_и_разбор.xlsx" --output work/acceptance/results
```

Проверка внутри собранного образа с отключённой сетью, пример PowerShell. Переменная `$dataDir` указывает на первичку **без эталона**; `$referenceDir` — отдельный каталог эталона. Монтируются только для этого запуска, в образ не копируются:

```powershell
$dataDir = (Resolve-Path './work/input').Path
$referenceDir = (Resolve-Path './work/acceptance/reference/данные').Path
$checksDir = (Resolve-Path './tests').Path
docker run --rm --network none `
  --mount "type=bind,source=$dataDir,target=/inputs,readonly" `
  --mount "type=bind,source=$referenceDir,target=/reference,readonly" `
  --mount "type=bind,source=$checksDir,target=/checks,readonly" `
  -e PYTHONPATH=/app kfz-local python /checks/acceptance.py `
  --input /inputs --reference '/reference/!Правильные_ответы_и_разбор.xlsx' --output /tmp/acceptance
```

Для проверки изменённых копий используйте опцию `--mutations` приёмочного скрипта. Оригиналы остаются неизменными, копии создаются в каталоге результатов.

## Ограничения первой версии

Поддержана выданная форма и виды документов комплекта. Полнота разовых актов без реестра **не проверена**. Трудоёмкость, материальные затраты и отсутствующие детальные разбивки не подтверждаются. Общий итог ограничен четырьмя проверяемыми верхнеуровневыми статьями. Расхождение не устанавливает его бухгалтерскую причину: для объяснения лишних 12 500 руб. в КФЗ нужен регистр формирования отчёта.

Следующие шаги: реестр для контроля полноты, дополнительные формы и локальная модель, предлагающая статью для спорного назначения с подтверждением проверяющим.

В предоставленном архиве были прочитаны оба README. Отдельный файл `Описание кейса для участников.docx` в архиве и Downloads не найден; требования взяты из пользовательского задания, а документы используются как входные данные. README набора называют разные номера кейса (19 и 5), но договор, период и нужная строка совпадают.

## Защита за 2–3 минуты

1. **0:00–0:30.** Загрузить КФЗ и комплект, показать договор, строку, период, нажать «Проверить».
2. **0:30–1:30.** Показать +12 500 руб.; открыть 0800, формулу, четыре источника и фрагмент КФЗ.
3. **1:30–2:00.** Показать нулевую разницу 0900 и журнал: ADM-27 — копия, ОРГ-0603 — июнь, ADM-75 — другой договор.
4. **2:00–2:30.** Убрать февральскую ведомость, повторить проверку, показать подтверждённую часть и «Недостаточно данных».

Фактические результаты проверки поставки находятся в `verification.txt` рядом с README в поставляемом архиве; в рабочем каталоге — `outputs/verification.txt`.
