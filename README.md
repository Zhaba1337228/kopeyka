# Копейка — разобраться до копейки

Локальное приложение для сверки карточки фактических затрат с первичными документами. React/JavaScript показывает суммы, точные источники и исключения; Python рассчитывает результат. Новый сценарий связывает **разбор расхождения → запрос коллеге → добавление ответа → сравнение версий**.

Исходный пример: договор `24/03/15-01`, строка «3 этап, 2026 г.», период январь–май 2026. Список статей больше не ограничен четырьмя кодами: он формируется из отчёта и документов. Поддержаны исходная форма с кодами в заголовках граф и таблица «Код статьи / Наименование / Сумма». Произвольные формы могут требовать адаптации. Исходные документы и эталон не входят в репозиторий и Docker-образ.

## Запуск и остановка

Нужны Docker Engine с Compose v2 или Docker Desktop в режиме Linux containers, свободный порт 8502 и около 4 ГБ доступной памяти. Первая сборка скачивает Debian, Python и npm-зависимости. После сборки расчёт, OCR и подготовка запросов работают без внешних API и без передачи документов третьим сторонам.

Из корня репозитория:

```sh
docker compose up --build -d
docker compose ps
```

Открыть [Копейку](http://localhost:8502). Переменная `KOPEYKA_PORT` меняет внешний порт. Проверка конфигурации: `docker compose config --quiet`. Диагностика: `docker compose logs --tail=100`.

```sh
docker compose stop
docker compose start
docker compose down
```

Остановка и `down` сохраняют именованный том с историей. **`docker compose down -v` удаляет документы и результаты**, для обычной остановки эта команда не нужна. Повторный запуск — `docker compose up -d`. Существующий том другой ручной установки автоматически не подключается: перенесите его отдельно или явно задайте имя тома.

Приложение внутри контейнера слушает 8501; Compose публикует его только на `127.0.0.1:8502`. Контейнер работает от непривилегированного пользователя, с файловой системой только для чтения, отдельными writable volume и tmpfs, без дополнительных capabilities. Лимиты Compose: 2 CPU, 2 ГБ RAM, 256 процессов. Загрузка большой партии OCR может занять несколько минут.

## Сценарий 1. Проверить полный комплект

1. В «Новую сверку» загрузить карточку КФЗ отдельно, затем 22 подтверждающих документа или ZIP. Поддержаны PDF, PNG/JPG, XLSX, DOCX.
2. Указать договор и период, нажать «Начать сверку». При нескольких подходящих строках отчёта выбрать строку явно.
3. В результатах выбрать 0800: **1 145 798,10 − 1 133 298,10 = +12 500,00 ₽**.
4. В «Разобраться до копейки» посмотреть формулу и четыре источника. Нажатие на источник открывает его фрагмент; доступен исходный файл. Для КФЗ также есть отдельный источник.
5. Открыть журнал: копия ADM-27, июньский ОРГ-0603 и ADM-75 другого договора исключены по разным причинам.
6. Скачать итоговое заключение TXT с разделением совпадений, расхождений и непроверенных статей, ссылками на имена/страницы/ячейки источников и ограничениями.

Эталон `!Правильные_ответы_и_разбор.xlsx` используется только независимой приёмкой. Он исключается из загрузки и не используется расчётом.

## Сценарий 2. Получить документ и сравнить версии

1. Загрузить комплект **без `02_02_Ведомость_ЗП_Февраль_2026.xlsx`**.
2. По 0200 будет «Недостаточно данных»: подтверждена часть **4 441 474,83 ₽**. Это не окончательная ошибка отчёта. По 0800 остаётся расхождение **12 500,00 ₽**.
3. Выбрать статью, перейти в «Запросить уточнение». Тема, договор, период, суммы, статус и источники уже заполнены. Отредактировать текст, сохранить черновик, скопировать или скачать TXT. Автоматической отправки сообщений нет.
4. В «Добавить ответ» загрузить февральскую ведомость и оставить комментарий. Создаётся версия 2 с отдельными копиями исходников.
5. Сравнение показывает по 0200 **+1 117 000,00 ₽** подтверждённых расходов, итог **5 558 474,83 ₽**, статус «Совпадает». По 0800 ничего не меняется: расхождение всё ещё **12 500,00 ₽**.
6. Через выбор версии или историю открыть версию 1: старый расчёт, источники и сохранённый запрос доступны. Черновик относится к конкретной статье конкретной версии.
7. Повторно добавить ту же ведомость: дубликат не увеличивает сумму. Добавление повреждённого файла отмечает недостаток данных, а не успешное закрытие вопроса.

Результаты завершённой версии не перезаписываются. Ручное решение проверяющего также создаёт новую версию. Можно продолжить любую старую версию: сравнение выполняется с её непосредственным родителем, номер версии уникален в семействе. Файлы разных версий хранятся отдельными копиями, поэтому расход диска растёт.

## Статьи, которых нет в исходном наборе

Организаторы подтвердили возможность новых статей на проверке. Коды 0400–0700 и другие четырёхзначные коды читаются из формы; их названия берутся из отчёта. Названия для неизвестных кодов не придумываются.

- В исходной альбомной форме границы граф определяются по сетке и заголовкам, а не четырём фиксированным координатам. Для сгруппированных зарплаты и взносов берётся первая итоговая графа, без повторного суммирования вложенных расшифровок. Вертикальная структура этой формы сохраняет исходный шаблон.
- В таблице по строкам требуется заголовок «Код статьи», «Наименование», «Сумма», одна денежная сумма на строку, отдельный итог, договор и строка «3 этап, ГГГГ г.». Поддержаны текстовый PDF и скан. Несколько сумм или повторный код не разрешаются догадкой.
- Явный реквизит первички «Статья калькуляции: 0400» связывает документ с кодом. Если реквизита нет, применяются существующие признаки 0800/0900; неизвестная связь требует решения проверяющего. В журнале доступны все статьи текущей сверки.
- Для дополнительной XLSX-формы читается единственная сумма в соседней справа ячейке от подписи «Итого», «К оплате» или «Сумма»; явные единицы берутся из подписи. Неподдерживаемая форма не исключается молча: она отмечается как непрочитанная.
- Отсутствие документов по новой статье даёт «Недостаточно данных», даже при нулевой отчётной сумме. Статья только из первички показывается без отчётной суммы и требует уточнения. Программа не заменяет неизвестное значение нулём.
- Некодированная ненулевая графа расходов отображается по заголовку и номеру графы, без приписывания ей вымышленного кода. Полнота некодированных нулевых граф отдельно не подтверждается.
- Сравнение версий выдерживает появление и исчезновение статей. При отсутствии статьи в одной версии изменение суммы не вычисляется из вымышленного нуля.

Универсальное чтение любой бухгалтерской формы не заявляется. Новый код и новая структура документа — разные задачи; для незнакомой структуры приложение сообщает о недостатке данных или неподдерживаемом отчёте.

## Архитектура и расчёт

`React → FastAPI → проверка загрузок → извлечение и OCR → привязка к статье/договору/периоду → исключение дублей → Decimal → доказательства → разбор и сравнение версий`

| Компонент | Назначение |
|---|---|
| `frontend/src.jsx`, `Controls.jsx`, `History.jsx` | Загрузка, результаты, просмотр источников, журнал, история |
| `frontend/Review.jsx` | Разбор, редактор запроса, добавление документов, сравнение |
| `backend.py` | API, изоляция по cookie, сохранение и восстановление версий, экспорт |
| `ui/uploads.py` | Ограниченная распаковка ZIP, проверка имён, размеров и сигнатур |
| `kfz_core/` | Общее ядро извлечения и расчёта для API и CLI |
| `kfz_core/review.py` | Объяснения из фактов, категории проблем, сравнение Decimal |
| `kfz_core/articles.py`, `report_tables.py` | Явные коды статей и чтение отчётной таблицы по строкам |
| `config/` | Признаки классификации статей |
| `tests/` | Независимая приёмка и API-тесты; эталон передаётся отдельно |

PDF с текстом читается PyMuPDF; сканы — локальным Tesseract `rus+eng`. КФЗ извлекается по областям граф. XLSX читается openpyxl, DOCX — python-docx. Источник сохраняет документ, значение и страницу/область, ячейку либо строку таблицы.

Деньги считаются через `Decimal` с точностью до копейки. Разница всегда **КФЗ минус документы**, включая отрицательные значения. Нижестоящие разбивки повторно не добавляются к итогу. Зарплата: `Ведомость!C6:C7`, итог C8 без кэша пересчитывается из деталей. Взносы: `Расчет взносов!B6`; A6 содержит базу, а не взносы.

При наличии периода услуги используется период; иначе дата документа. Другой договор/период исключается с отдельной причиной. SHA-256 выявляет точные копии; реквизиты — повторные документы. Разные суммы при одинаковых реквизитах требуют решения проверяющего. Причина ручного решения сохраняется вместе с прежним состоянием документа.

Объяснения и запросы формируются детерминированно из расчёта. Программа не придумывает бухгалтерскую причину разницы. Отсутствие месячного документа, неоднозначная связь и ошибка чтения отделены от подтверждённого расхождения. Ошибка неклассифицированного файла консервативно делает все статьи неполностью проверенными.

## Хранение и границы защиты

- Оригиналы пользователя не изменяются. Рабочие копии, доказательства и JSON-манифесты находятся в `runtime/jobs`; путь задаёт `KOPEYKA_STORAGE`.
- JSON сохраняется через временный файл и атомарную замену. При перезапуске результаты, версии и черновики восстанавливаются из тома. Незавершённая обработка помечается как прерванная, автоматически не возобновляется.
- История и источники доступны владельцу случайного HttpOnly cookie с SameSite=Strict. Это демонстрационная изоляция браузеров, **не учётные записи**. Очистка cookie лишает браузер доступа к прежней истории.
- Ограничения загрузки: 500 файлов, 250 МБ; учитывается распаковка ZIP/Office. Проверяются сигнатуры. Имена из ZIP не используются как пути; макросы в Office отклоняются. Вложенные архивы не распаковываются.
- Хранилище не шифруется, антивируса и автоматической очистки нет. Нужны резервные копии тома, контроль свободного места и доступов на хосте.
- Для рабочего многопользовательского размещения нужны HTTPS, учётные записи, изолированные задания с таймаутами, квоты, сроки хранения и защищённое хранилище.
- API запускается **одним worker**: индекс сессий в памяти, сохранение — на диск. Несколько процессов/реплик пока не поддерживаются. Добавления и ручные пересчёты сериализованы внутри процесса.

## Разработка без Docker

Python 3.11, Node.js 22, Tesseract с `rus+eng`. Python-зависимости закреплены в `requirements.txt`, frontend — в `frontend/package-lock.json`. В PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
.\.venv\Scripts\python -m uvicorn backend:app --host 127.0.0.1 --port 8000
```

Во втором терминале:

```powershell
cd frontend
npm ci
npm run dev
```

Открыть адрес Vite из терминала (обычно 5173). `/api` проксируется на 8000. Остановка — Ctrl+C. Для production-сборки выполнить `npm run build`: API отдаёт `frontend/dist`. `TESSERACT_CMD` задаёт путь к Tesseract, `TESSDATA_PREFIX` — к языковым данным.

`app.py` — оставшийся отдельный интерфейс Streamlit. Новые версии, запросы и сравнение доступны в React/FastAPI. Streamlit Community Cloud не является способом запуска этого Docker-приложения.

## Проверки

Пути к конфиденциальным данным задаются отдельно; в Git их не добавлять.

```sh
python -m unittest discover -s tests -p test_review.py
python -m unittest discover -s tests -p test_articles.py
python tests/acceptance.py --input "/path/to/данные" --reference "/path/to/!Правильные_ответы_и_разбор.xlsx" --output work/acceptance/results --mutations
python tests/versions_api.py --input "/path/to/данные" --url http://127.0.0.1:8502
```

Приёмка проверяет эталонные суммы, исключение другого договора/периода и мутации копий: изменение суммы, пропуск, дубли, повреждение, неоднозначность, ручное решение, выбор строки КФЗ. Оригиналы не меняются. API-тест проверяет версии и ветвление, запрос, сравнение, доступ к источникам, разные cookie, дубли и испорченный файл.

Браузерные проверки (PowerShell, из `frontend`):

```powershell
npx playwright install chromium
$env:KOPEYKA_TEST_URL='http://127.0.0.1:8502'
$env:KOPEYKA_TEST_INPUT='C:\path\to\данные'
npx playwright test tests/history.spec.js tests/review.spec.js --workers=1
```

Без `KOPEYKA_TEST_INPUT` тест реального комплекта пропускается; история проверяется с тестовыми ответами API. Реальный сценарий проверяет разбор, сохранение запроса, добавление ведомости, неизменность старой версии и мобильную ширину.

Тесты новых кодов используют искусственные данные, не эталон кейса. Для двух OCR-сценариев установите `KOPEYKA_TEST_OCR=1` и Tesseract `rus+eng`; без этой переменной эти два теста пропускаются. Проверяются 0400–0700, новый код только из первички, неоднозначность, незнакомая XLSX и ручная корректировка связи. Для браузерного сценария:

```powershell
# Из корня проекта
.\.venv\Scripts\python tests/new_articles_fixtures.py --output work/new-articles
$env:KOPEYKA_TEST_ARTICLES=(Resolve-Path work/new-articles).Path
$env:KOPEYKA_TEST_URL='http://127.0.0.1:8502'
cd frontend
npx playwright test tests/articles.spec.js --workers=1
```

Независимую приёмку можно запустить в образе с `--network none`, примонтировав входы, эталон и `tests` только для чтения и передав `PYTHONPATH=/app`. Расчёт не требует сети.

## Ограничения и защита кейса

В исходном комплекте проверяются четыре верхнеуровневые статьи; в расширенном отчёте состав определяется прочитанными кодами. Полнота разовых актов без реестра, трудоёмкость и отсутствующие разбивки не подтверждаются. Совпадение сумм не означает достоверность всех показателей отчёта. Для причины лишних 12 500 ₽ нужен регистр формирования КФЗ.

[Соответствие критериям, демонстрация и план развития](docs/case-coverage.md). Оценку выставляет жюри; наличие функции само по себе не гарантирует баллы.
