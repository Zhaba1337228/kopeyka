# Копейка — разобраться до копейки

Локальное приложение для сверки карточки фактических затрат с первичными документами. React/JavaScript показывает суммы, точные источники и исключения; Python рассчитывает результат. Новый сценарий связывает **разбор расхождения → запрос коллеге → добавление ответа → сравнение версий**.

Исходный пример: договор `24/03/15-01`, строка «3 этап, 2026 г.», период январь–май 2026. Список статей больше не ограничен четырьмя кодами: он формируется из отчёта и документов. Поддержаны исходная форма с кодами в заголовках граф и таблица «Код статьи / Наименование / Сумма». Произвольные формы могут требовать адаптации. Исходные документы и эталон не входят в репозиторий и Docker-образ.

## Онлайн-демонстрация

Открыть [Копейку](https://hackathon.bravateam.firemail.icu/). Приложение открывается сразу, без авторизации.

Демонстрация доступна всем посетителям. Используйте на сайте только учебные документы; для работы с конфиденциальными данными нужны индивидуальные учётные записи и защищённое хранение.

На сервере приложение работает в контейнере `kopeyka`; Nginx принимает HTTPS и проксирует запросы на `127.0.0.1:8502`. Документы и история хранятся в Docker-томе `kopeyka-data`. Сертификат Let's Encrypt обновляется через Certbot, после обновления Nginx перезагружает конфигурацию. Проверка состояния на сервере:

```sh
docker ps --filter name=kopeyka
docker logs --tail=100 kopeyka
systemctl status nginx certbot.timer
```

Серверная демонстрация запущена отдельной командой `docker run`; инструкции Compose ниже относятся к локальному запуску.

## Запуск и остановка

Нужны Docker Engine с Compose v2 или Docker Desktop в режиме Linux containers, свободный порт 8502 и около 4 ГБ доступной памяти. Первая сборка скачивает Debian, Python и npm-зависимости. После сборки расчёт, OCR и подготовка запросов работают без внешних API и без передачи документов третьим сторонам.

Из корня репозитория:

```sh
docker compose up --build -d
docker compose ps
```

Открыть [Копейку](http://localhost:8502). Переменная `KOPEYKA_PORT` меняет внешний порт. Проверка конфигурации: `docker compose config --quiet`. Диагностика: `docker compose logs --tail=100`.

```sh
docker compose stop
docker compose start
docker compose down
```

Остановка и `down` сохраняют именованный том с историей. **`docker compose down -v` удаляет документы и результаты**, для обычной остановки эта команда не нужна. Повторный запуск — `docker compose up -d`. Существующий том другой ручной установки автоматически не подключается: перенесите его отдельно или явно задайте имя тома.

Приложение внутри контейнера слушает 8501; Compose публикует его только на `127.0.0.1:8502`. Контейнер работает от непривилегированного пользователя, с файловой системой только для чтения, отдельными writable volume и tmpfs, без дополнительных capabilities. Лимиты Compose: 2 CPU, 2 ГБ RAM, 256 процессов. Загрузка большой партии OCR может занять несколько минут.

## Сценарий 1. Проверить полный комплект

1. В «Новую сверку» загрузить карточку КФЗ отдельно, затем 22 подтверждающих документа или ZIP. Поддержаны PDF, PNG/JPG, XLSX, DOCX.
2. Указать договор и период, нажать «Начать сверку». При нескольких подходящих строках отчёта выбрать строку явно.
3. В результатах выбрать 0800: **1 145 798,10 − 1 133 298,10 = +12 500,00 ₽**.
4. В «Разобраться до копейки» посмотреть формулу и четыре источника. Нажатие на источник открывает его фрагмент; доступен исходный файл. Для КФЗ также есть отдельный источник.
5. Открыть журнал: копия ADM-27, июньский ОРГ-0603 и ADM-75 другого договора исключены по разным причинам.
6. Скачать заключение TXT или Excel: общие суммы, количество совпадений/расхождений/непроверенных статей, детальные показатели и источники. Excel содержит пять листов, включая документы и решения проверяющего.

Эталон `!Правильные_ответы_и_разбор.xlsx` используется только независимой приёмкой. Он исключается из загрузки и не используется расчётом.

## Сценарий 2. Получить документ и сравнить версии

1. Загрузить комплект **без `02_02_Ведомость_ЗП_Февраль_2026.xlsx`**.
2. По 0200 будет «Недостаточно данных»: подтверждена часть **4 441 474,83 ₽**. Это не окончательная ошибка отчёта. По 0800 остаётся расхождение **12 500,00 ₽**.
3. Выбрать статью, перейти в «Запросить уточнение». Тема, договор, период, суммы, статус и источники уже заполнены. Отредактировать текст, сохранить черновик, скопировать или скачать TXT. Автоматической отправки сообщений нет.
4. В «Добавить ответ» загрузить февральскую ведомость и оставить комментарий. Создаётся версия 2 с отдельными копиями исходников.
5. Сравнение показывает по 0200 **+1 117 000,00 ₽** подтверждённых расходов, итог **5 558 474,83 ₽**, статус «Совпадает». По 0800 ничего не меняется: расхождение всё ещё **12 500,00 ₽**.
6. Через выбор версии или историю открыть версию 1: старый расчёт, источники и сохранённый запрос доступны. Черновик относится к конкретной статье конкретной версии.
7. Повторно добавить ту же ведомость: дубликат не увеличивает сумму. Добавление повреждённого файла отмечает недостаток данных, а не успешное закрытие вопроса.

Результаты завершённой версии не перезаписываются. Ручное решение проверяющего также создаёт новую версию. Можно продолжить любую старую версию: сравнение выполняется с её непосредственным родителем, номер версии уникален в семействе. Файлы разных версий хранятся отдельными копиями, поэтому расход диска растёт.

## Попробовать без исходного набора кейса

В приложении откройте «О проверке» и нажмите «Скачать учебный комплект». Это синтетические документы, которые создаются локально; конфиденциальные материалы кейса не используются. Архив также доступен по `/api/demo`.

Распакуйте внешний ZIP. Загрузите `01_Учебная_КФЗ.pdf` как КФЗ и `02_Комплект_первой_сверки.zip` как подтверждающие документы. Договор `DEMO-2026/01`, период **01.01.2026–31.05.2026**. В форме указан этап 4. Статья 0400 проверяет перевод тысяч рублей, 0500 — выбор суммы к оплате при наличии НДС, 0700 — недостаток документа, 0800 — расхождение 100 ₽. Затем добавьте `03_Ответ_коллеги.docx` через «Добавить ответ»: 0700 закроется, а расхождение 0800 останется. Подтверждённый итог вырастет с **102 600 ₽** до **103 100 ₽** при сумме КФЗ **103 200 ₽**.

## Уточнить сумму по источнику

В журнале нажмите на имя документа. Слева доступны его фрагменты и оригинал, справа — решение проверяющего. Если сумма или единицы неоднозначны, выберите нужный фрагмент, отметьте «Подтвердить сумму по выбранному фрагменту», введите исходное число и единицу (рубли / тысячи / миллионы). При необходимости раскройте «Уточнить реквизиты». Укажите основание и пересчитайте.

Сохранится новая версия, исходный файл и распознанное значение останутся неизменными. В источнике новой суммы хранятся введённое число, множитель и основание. Сумму нельзя привязать к фрагменту другого документа; точный дубликат нельзя включить повторно. Если файл вообще не читается, нужно добавить исправленный документ.

Блок «Другие показатели КФЗ» отдельно показывает трудоёмкость и денежные расшифровки, найденные по заголовкам. Основная зарплата, дополнительные начисления и резерв связываются по подписям первичных регистров. Объединённая сумма доплат с резервом не подтверждает каждую часть отдельно; если отдельные источники есть, они проверяются отдельно и используются для составных показателей. Для разбивок без достаточного источника выводится «Недостаточно данных», даже если в КФЗ стоит ноль. Эти показатели не суммируются с основными статьями.

## Статьи, которых нет в исходном наборе

Организаторы подтвердили возможность новых статей на проверке. Коды 0400–0700 и другие четырёхзначные коды читаются из формы; их названия берутся из отчёта. Названия для неизвестных кодов не придумываются.

- В альбомной форме таблица обнаруживается по линиям на изображении целиком. Положение на странице, границы строк и столбцов не заданы координатами шаблона. Для сгруппированных граф итог определяется по иерархии объединённых ячеек заголовка и подписи «Всего»/«Итого». Расшифровки связываются по их названиям, без повторного суммирования. Неоднозначная структура требует уточнения.
- В таблице по строкам требуется заголовок «Код статьи», «Наименование», «Сумма», одна денежная сумма на строку, отдельный итог, договор и строка «N этап, ГГГГ г.». Номер этапа читается из отчёта; поддержаны текстовый PDF и скан. Несколько сумм или повторный код не разрешаются догадкой.
- Явный реквизит первички «Статья калькуляции: 0400» связывает документ с кодом. Если реквизита нет, применяются существующие признаки 0800/0900; неизвестная связь требует решения проверяющего. В журнале доступны все статьи текущей сверки.
- В XLSX денежные столбцы определяются по заголовкам, значения — по подписям строк. Название листа, номер строки и буква столбца не задают тип документа или сумму. База взносов и авансы не считаются начислениями. При наличии полного набора непересекающихся компонентов они суммируются и проверяются против явно указанного числового итога. Неизвестное дополнительное начисление или противоречивый итог требуют решения. Произвольные Excel-формулы не исполняются.
- Отсутствие документов по новой статье даёт «Недостаточно данных», даже при нулевой отчётной сумме. Статья только из первички показывается без отчётной суммы и требует уточнения. Программа не заменяет неизвестное значение нулём.
- Некодированная ненулевая графа расходов отображается по заголовку и номеру графы, без приписывания ей вымышленного кода. Полнота некодированных нулевых граф отдельно не подтверждается.
- Сравнение версий выдерживает появление и исчезновение статей. При отсутствии статьи в одной версии изменение суммы не вычисляется из вымышленного нуля.

Универсальное чтение любой бухгалтерской формы не заявляется. Новый код и новая структура документа — разные задачи; для незнакомой структуры приложение сообщает о недостатке данных или неподдерживаемом отчёте.

## Архитектура и расчёт

`React → FastAPI → проверка загрузок → извлечение и OCR → привязка к статье/договору/периоду → исключение дублей → Decimal → доказательства → разбор и сравнение версий`

| Компонент | Назначение |
|---|---|
| `frontend/src.jsx`, `Controls.jsx`, `History.jsx` | Загрузка, результаты, просмотр источников, журнал, история |
| `frontend/Review.jsx` | Разбор, редактор запроса, добавление документов, сравнение |
| `frontend/Documents.jsx` | Просмотр спорного источника, уточнение суммы/единиц/реквизитов, детальные показатели |
| `backend.py` | API, изоляция по cookie, сохранение и восстановление версий, экспорт |
| `ui/uploads.py` | Ограниченная распаковка ZIP, проверка имён, размеров и сигнатур |
| `kfz_core/` | Общее ядро извлечения и расчёта для API и CLI |
| `kfz_core/review.py` | Объяснения из фактов, категории проблем, сравнение Decimal |
| `kfz_core/articles.py`, `report_tables.py` | Явные коды статей и чтение отчётной таблицы по строкам |
| `kfz_core/amounts.py`, `money.py`, `metadata.py` | Выбор суммы, единицы, точные вычисления, договоры |
| `kfz_core/tabular.py`, `grid.py` | Поиск ячеек по смысловым подписям и таблиц по фактической сетке |
| `kfz_core/periods.py`, `formulas.py` | Даты документа, покрытие интервалов, контроль пересечений и ограниченный расчёт формул |
| `kfz_core/coverage.py`, `export.py`, `demo.py` | Детальные показатели, Excel, публичный учебный комплект |
| `config/` | Признаки классификации статей |
| `tests/` | Независимая приёмка и API-тесты; эталон передаётся отдельно |

PDF с текстом читается PyMuPDF; сканы — локальным Tesseract `rus+eng`. КФЗ извлекается по областям граф. XLSX читается openpyxl, DOCX — python-docx. Источник сохраняет документ, значение и страницу/область, ячейку либо строку таблицы.

Деньги считаются через `Decimal` с точностью до копейки. Разница всегда **КФЗ минус документы**, включая отрицательные значения. Нижестоящие разбивки повторно не добавляются к итогу. Сумма зарплаты получается из подписанных компонентов начислений, взносы — из столбца начисленных взносов. Адреса фактически найденных значений, подписей и заголовков сохраняются в доказательствах. Числа не берутся из эталона, имён файлов или заранее заданных ячеек.

Единицы учитываются в строке, заголовке таблицы и явном объявлении документа. Перевод тысяч/миллионов выполняется **до** округления до копейки; поддержаны целые суммы, минус и отрицательное число в скобках. Противоречащие единицы требуют решения проверяющего. «Итого к оплате» имеет приоритет над промежуточной суммой; итог и НДС могут находиться в одной строке. НДС, сумма без НДС и аванс отдельно не прибавляются к итогу. Конкурирующие итоги не выбираются наугад. Договоры могут иметь буквенные префиксы, например `МФТИ-2026/01`.

При наличии периода услуги используется период; иначе дата самого документа. Дата и срок действия договора не подменяют дату акта. Поддержаны месяцы, числовые кварталы и интервалы дат; неполный месяц не считается полным. Справка за квартал покрывает весь указанный интервал. Пересекающиеся регистры начислений требуют решения, чтобы месячные суммы не складывались с квартальным итогом. Другой договор/период исключается с отдельной причиной. SHA-256 выявляет точные копии; реквизиты — повторные документы. Разные суммы при одинаковых реквизитах требуют решения проверяющего. Причина ручного решения сохраняется вместе с прежним состоянием документа.

Для XLSX поддержан ограниченный расчёт `SUM`, `ROUND`, арифметики `+ - * /`, скобок, ссылок на ячейки и диапазоны, включая другой лист того же файла. Расчёт идёт в Decimal по исходным ячейкам; устаревший кэш Excel не используется. В доказательствах и Excel-выгрузке сохраняются формула и ячейки расчёта. Внешние ссылки, неизвестные функции, циклы, пустые/текстовые операнды и превышение лимитов требуют проверки. Макросы и Excel не запускаются. В регистрах по сотрудникам суммы строк сверяются с промежуточными итогами, которые повторно не прибавляются.

Трудоёмкость подтверждается отдельным регистром в **чел.-мес.**; часы не переводятся без основания. Материальные затраты, включая явно указанный ноль, подтверждаются независимым источником. Отсутствие регистра не считается нулём. Разбивки зарплаты и взносов проверяются по отдельным подписанным составляющим в XLSX, DOCX и текстовом PDF. Данные независимых регистров не прибавляются повторно к денежному итогу. Изменения деталей видны при сравнении версий.

Если сумма в найденной графе КФЗ не читается или распознана неверно, откройте «Проверить значение в КФЗ»: выберите показатель, сверяйте выделенный фрагмент, укажите значение, единицу и основание. Подтверждение привязано к конкретной ячейке и строке отчёта, сохраняется в новой версии и последующих пересчётах. Исходное значение и оригинал не изменяются; контроль суммы статей против итога остаётся обязательным. Если структура КФЗ вообще не распознана и фрагмент не найден, произвольный ввод отчёта не допускается.

Объяснения и запросы формируются детерминированно из расчёта. Программа не придумывает бухгалтерскую причину разницы. Отсутствие месячного документа, неоднозначная связь и ошибка чтения отделены от подтверждённого расхождения. Ошибка неклассифицированного файла консервативно делает все статьи неполностью проверенными.

## Хранение и границы защиты

- Оригиналы пользователя не изменяются. Рабочие копии, доказательства и JSON-манифесты находятся в `runtime/jobs`; путь задаёт `KOPEYKA_STORAGE`.
- JSON сохраняется через временный файл и атомарную замену. При перезапуске результаты, версии и черновики восстанавливаются из тома. Незавершённая обработка помечается как прерванная, автоматически не возобновляется.
- История и источники доступны владельцу случайного HttpOnly cookie с SameSite=Strict. Это демонстрационная изоляция браузеров, **не учётные записи**. Очистка cookie лишает браузер доступа к прежней истории.
- Ограничения загрузки: 500 файлов, 250 МБ; учитывается распаковка ZIP/Office. Проверяются сигнатуры. Имена из ZIP не используются как пути; макросы в Office отклоняются. Вложенные архивы не распаковываются.
- Хранилище не шифруется, антивируса и автоматической очистки нет. Нужны резервные копии тома, контроль свободного места и доступов на хосте.
- Для рабочего многопользовательского размещения нужны HTTPS, учётные записи, изолированные задания с таймаутами, квоты, сроки хранения и защищённое хранилище.
- API запускается **одним worker**: индекс сессий в памяти, сохранение — на диск. Несколько процессов/реплик пока не поддерживаются. Добавления и ручные пересчёты сериализованы внутри процесса.

## Разработка без Docker

Python 3.11, Node.js 22, Tesseract с `rus+eng`. Прямые Python-зависимости перечислены в `requirements.txt`, полный набор закреплён в `requirements.lock`; frontend — в `frontend/package-lock.json`. Docker использует lock-файлы и базовые образы по digest. Debian-пакеты устанавливаются из репозитория дистрибутива; побитовая воспроизводимость образа не заявляется. В PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.lock
.\.venv\Scripts\python -m uvicorn backend:app --host 127.0.0.1 --port 8000
```

Во втором терминале:

```powershell
cd frontend
npm ci
npm run dev
```

Открыть адрес Vite из терминала (обычно 5173). `/api` проксируется на 8000. Остановка — Ctrl+C. Для production-сборки выполнить `npm run build`: API отдаёт `frontend/dist`. `TESSERACT_CMD` задаёт путь к Tesseract, `TESSDATA_PREFIX` — к языковым данным.

`app.py` — оставшийся отдельный интерфейс Streamlit. Новые версии, запросы и сравнение доступны в React/FastAPI. Streamlit Community Cloud не является способом запуска этого Docker-приложения.

## Проверки

Пути к конфиденциальным данным задаются отдельно; в Git их не добавлять.

```sh
python -m unittest discover -s tests -p 'test_*.py'
python tests/acceptance.py --input "/path/to/данные" --reference "/path/to/!Правильные_ответы_и_разбор.xlsx" --output work/acceptance/results --mutations
python tests/versions_api.py --input "/path/to/данные" --url http://127.0.0.1:8502
python tests/criteria_api.py --url http://127.0.0.1:8502
```

Приёмка проверяет эталонные суммы, исключение другого договора/периода и мутации копий: изменение суммы, пропуск, дубли, повреждение, неоднозначность, ручное решение, выбор строки КФЗ. Оригиналы не меняются. API-тест проверяет версии и ветвление, запрос, сравнение, доступ к источникам, разные cookie, дубли и испорченный файл.

`test_semantic_extraction.py` проверяет переименование листов, перестановку строк и столбцов, отличие аванса и базы взносов от начислений, целые суммы, итог с НДС в одной строке, противоречивый итог и перенос старого ручного решения по положению источника. OCR-проверка переносит таблицу КФЗ на другую область страницы и переставляет статьи. Независимая приёмка также переносит всю исходную КФЗ на увеличенную страницу и сравнивает суммы и детали.

`test_remaining_criteria.py` воспроизводит подмену даты акта датой договора, квартальное покрытие, частичные месяцы, пересечения и дубли; проверяет формулы без кэша, циклы и внешние ссылки, регистры по сотрудникам, трудоёмкость и материальные затраты, разбивки взносов, отсутствие двойного учёта, перестановку колонок КФЗ и числа в описаниях. Для браузерного сценария создайте `python tests/remaining_fixtures.py`, задайте `KOPEYKA_TEST_REMAINING` абсолютным путём к `work/remaining-fixtures` и запустите из `frontend` команду `npx playwright test tests/remaining.spec.js --workers=1` с адресом сервера в `KOPEYKA_TEST_URL`.

Браузерные проверки (PowerShell, из `frontend`):

```powershell
npx playwright install chromium
$env:KOPEYKA_TEST_URL='http://127.0.0.1:8502'
$env:KOPEYKA_TEST_INPUT='C:\path\to\данные'
npx playwright test tests/history.spec.js tests/review.spec.js --workers=1
```

Без `KOPEYKA_TEST_INPUT` тест реального комплекта пропускается; история проверяется с тестовыми ответами API. Реальный сценарий проверяет разбор, сохранение запроса, добавление ведомости, неизменность старой версии и мобильную ширину.

Тесты новых кодов используют искусственные данные, не эталон кейса. Для OCR-сценариев установите `KOPEYKA_TEST_OCR=1` и Tesseract `rus+eng`; без этой переменной OCR-тесты пропускаются. Проверяются 0400–0700, новый код только из первички, неоднозначность, незнакомая XLSX и ручная корректировка связи. Для браузерного сценария:

```powershell
# Из корня проекта
.\.venv\Scripts\python tests/new_articles_fixtures.py --output work/new-articles
$env:KOPEYKA_TEST_ARTICLES=(Resolve-Path work/new-articles).Path
$env:KOPEYKA_TEST_URL='http://127.0.0.1:8502'
cd frontend
npx playwright test tests/articles.spec.js --workers=1
```

Браузерная проверка подтверждения суммы, единиц, реквизитов и скачивания Excel использует отдельные синтетические файлы:

```powershell
# Из корня проекта
.\.venv\Scripts\python tests/criteria_fixtures.py --output work/criteria-fixtures
$env:KOPEYKA_TEST_CRITERIA=(Resolve-Path work/criteria-fixtures).Path
$env:KOPEYKA_TEST_URL='http://127.0.0.1:8502'
cd frontend
npx playwright test tests/criteria.spec.js --workers=1
```

Независимую приёмку можно запустить в образе с `--network none`, примонтировав входы, эталон и `tests` только для чтения и передав `PYTHONPATH=/app`. Расчёт не требует сети.

## Ограничения и защита кейса

В исходном комплекте проверяются четыре верхнеуровневые статьи; в расширенном отчёте состав определяется прочитанными кодами. Полнота разовых актов без реестра не устанавливается; детальные показатели без независимых источников остаются непроверенными. Часы не пересчитываются в человеко-месяцы без методики, неподдерживаемые формулы и нечитаемые формы требуют уточнения. Универсальный разбор перекошенных сканов и любых таблиц не заявляется. Совпадение сумм не означает достоверность всех показателей отчёта. Для причины лишних 12 500 ₽ нужен регистр формирования КФЗ.

[Соответствие критериям, демонстрация и план развития](docs/case-coverage.md). Оценку выставляет жюри; наличие функции само по себе не гарантирует баллы.
